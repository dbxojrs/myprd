## Q1 사용자
반도체 패키징을 처음 배우는 대학생(전자·재료·기계공학 3–4학년, 취업 준비생).
[가설] 수업이나 취업 준비 과정에서 특정 공정 이름은 들었지만 전체 흐름 속 위치는 모릅니다.

## Q2 문제
학생이 "쏘잉 공정이 뭐야?"처럼 공정 하나를 찾아보면 그 공정만 단편적으로 설명하는 자료가 나옵니다.
그 공정에 들어오는 입력(앞 공정의 결과물)과 나가는 결과(다음 공정의 입력)를 모르니, 공정이 왜 그런 조건으로 진행되는지 이해하지 못하고 암기로 끝납니다.
또 패키지 종류마다 공정 흐름이 다르다는 점을 모르고, 출처가 불분명한 자료에서 틀린 내용을 배우기도 합니다.
[가설] 흩어진 블로그·논문·업체 자료를 직접 순서대로 엮는 데 시간이 많이 듭니다.

## Q3 해법
학생이 먼저 패키지 종류를 고르면, 앱은 그 패키지의 장점과 쓰이는 곳을 설명하고 해당 패키지의 공정 흐름을 보여줍니다.
학생이 공정 하나를 물으면, 앱은 그 공정을 설명하는 데서 끝나지 않고 다음을 알려줍니다.
1. **선수 공정**: "이 공정을 이해하려면 먼저 이 공정들을 보세요"
2. **흐름 속 위치**: 선택한 패키지의 공정 흐름에서 현재 공정의 앞과 뒤
3. **시뮬레이션**: 공정 조건을 바꿔 보고 결과(불량 포함)가 어떻게 달라지는지 확인

공정을 하나씩 익힌 학생은 **패키징 라인 시뮬레이션**에서 첫 공정부터 마지막 공정까지 직접 조건을 골라 진행하고, 마지막에 완성된 패키지가 제대로 기능하는지 판정받습니다. 앞 공정의 선택이 뒤 공정의 결과에 영향을 준다는 점을 체험합니다.

기본 공정을 익힌 학생은 **Advanced Package 심화 학습**으로 넘어가, 첨단 패키지가 어떤 공정을 쓰는지, 왜 중요한지, 앞으로 어떤 기술이 개발되는지 배웁니다.

모든 설명은 검수된 공정 데이터와 무료로 공개된 학술 출처에 근거합니다. 근거를 찾지 못하면 추측하지 않고 "확인되지 않음"으로 표시합니다.

## Q4 기능 6개
1. **패키지를 고른다**: 패키지 버튼을 누르면 그 패키지의 장점, 쓰이는 곳(제품·산업), 공정 흐름을 보여줍니다.
2. **공정을 묻는다**: 공정 이름을 입력하거나 고르면 설명, 핵심 용어, 학습 자료, 출처를 보여줍니다.
3. **선수 공정을 따라간다**: 앞 공정을 학습 순서대로 추천하고, 흐름도에서 현재 위치를 강조합니다. 이미 학습한 공정은 완료로 표시합니다.
4. **공정을 시뮬레이션한다**: 조건 2–3개(예: 블레이드 속도, 접착 온도)를 바꾸면 결과와 대표 불량을 보여줍니다.
5. **Advanced Package를 탐구한다**: 첨단 패키지(2.5D, 3D, 칩렛 등)를 고르면 핵심 공정, 중요한 이유, 쓰이는 곳, 앞으로 개발될 기술을 보여주고, 기본 공정과의 연결(예: 웨이퍼 쏘잉 → 하이브리드 본딩 전 다이 준비)을 알려줍니다.
6. **패키징 라인을 끝까지 진행한다**: 선택한 패키지의 공정을 순서대로 진행하며, 공정마다 변수별 선택지(1, 2, 3 중 하나)를 고릅니다. 마지막 공정이 끝나면 패키지가 **정상 / 신뢰성 위험 / 불량** 중 어디에 해당하는지와 원인 공정, 이유, 다시 볼 공정을 보여줍니다.
   - 기능 4는 공정 하나의 조건을 바꿔 보는 연습이고, 기능 6은 전체 공정을 이어서 진행하는 실전입니다.
   - 최종 판정 화면에는 **공정별 진단**(공정마다 등급, 문제, 이유, 연결)과 **완성된 패키지 상태**(단면 그림에 문제 부위 표시, "테스트에서 걸리는 문제"와 "출하 후 나타날 수 있는 문제")를 보여줍니다.
   - "공정마다 결과 바로 보기"를 켜면 공정을 고를 때마다 그 공정의 결과와 완성 패키지에 주는 영향을 바로 보여줍니다.

공통: 공정, 패키지, Advanced Package 설명마다 **"비유로 쉽게 보기"** 버튼을 둡니다. 누르면 일상 사물에 빗댄 설명이 펼쳐집니다. (예: 다이 어태치 = 바닥에 타일 붙이기) 비유는 단순화라는 안내를 함께 표시합니다.

공통: 첫 화면은 **홈**입니다. 배우기(전체 지도·전공정·패키지·후공정 흐름도·공정 질문), 실습(공정 시뮬레이션·라인 실습), 심화(Advanced Package)의 카테고리로 화면을 고르고, 전체 학습 진도와 "이어서 학습" 버튼을 보여줍니다. 위쪽 메뉴도 같은 카테고리로 묶습니다.

공통: **전체 공정 지도**는 칩 설계 → 전공정 → 팹 아웃·웨이퍼 출하/입고 → 웨이퍼 레벨 패키징(WLP) → 후공정 → 보드 실장의 6단계를 순서대로 보여주고, 단계마다 맡는 회사 유형(팹리스, 디자인하우스, 파운드리, OSAT, IDM, 세트·EMS)을 표시합니다. 단계를 누르면 안의 공정이 순서대로 펼쳐지고, 공정을 누르면 공정 설명으로 들어갑니다.
- 칩 설계: 사양 정의, 프론트엔드 설계(RTL), 기능 검증, 논리 합성, 백엔드 설계(물리 설계), 사인오프·테이프아웃, 포토마스크 제작
- 보드 실장: 완성된 패키지를 제품 기판에 붙이는 SMT

공통: 공정 설명 화면 위에는 "전체 지도 › 단계 › 순서. 공정" 경로를, 아래에는 **전체 순서 이동 막대**를 둡니다. "학습 완료하고 다음" 버튼으로 설계부터 보드 실장까지 차례로 따라갈 수 있고, 단계가 바뀌는 곳에서는 이번 단계의 결과와 다음 단계를 알려줍니다.
- 전공정: 8대 공정과 그 사이사이 반복되는 공정(세정, CMP, 열처리, ALD)
- 팹 아웃·웨이퍼 출하/입고: 웨이퍼 맵 전달, 웨이퍼 운반·보관, 입고 검사
- 웨이퍼 레벨 패키징(WLP): TSV, RDL, 범핑 (일부 패키지만 거침)
- **고급 장비 시뮬레이터** (실습 카테고리, 장비 14대: 전공정 6대 — 산화로, 노광·트랙, 건식 식각기, CVD, 이온 주입기, PVD / 후공정 8대 — 백그라인더, 다이싱 장비, 다이 본더, 와이어 본더, 몰딩 프레스, 레이저 마커, 패키지 쏘, 테스트 핸들러): 장비 조작반처럼 상태(로트·블레이드·패드 등)와 조건(회전수·이송·하중·초음파 등)을 정하고 START를 누르면 가동 순서대로 로그가 나오고, 문제가 있으면 그 단계에서 알람으로 멈춥니다. 끝나면 불량·경고·정상과 원인, 조치, 근거 출처를 보여줍니다.
  - 자유 조작 / 상황 실습(작업 지시서·목표·힌트, 조치 버튼: 드레싱, 블레이드 교체, 패드 세정, 캐필러리 교체)
  - 조건 값 표시 3가지: 단계+예시 숫자, 출처 숫자만(📖), 0~100% 상대값
  - 경광등, 상대 지표 게이지(처리 속도, 칩핑 위험, 접합 강도 등), 작업 이력
  - 장비 그림은 조건을 바꾸는 즉시 그 조건대로 움직이고(회전·이송 속도, 진동, 온도 색), 가동 중 이상이 생기면 그림에 증상이 나타납니다.
  - **라인 연결 실습**: 전공정 라인·후공정 라인(QFN)의 장비를 순서대로 돌립니다. 앞 장비의 조건·결과가 뒤 장비의 상태를 바꾸고(예: 백그라인딩을 얇게 → 다이싱에 얇은 웨이퍼로 도착, 접착제 과다 → 와이어 본더에 오염된 패드로 도착), 마지막에 장비별 판정과 완성품까지 남는 영향으로 라인 최종 판정(정상/신뢰성 위험/불량)을 보여줍니다. 연결 규칙은 machineLine.js에 있습니다.
  - 판정은 규칙표(data/machines/*.js, machineLine.js)로만 계산합니다. `npm run check-machines`로 규칙표를 검사합니다. 출처: TPT "Wire Bonding Basics" 4·21~23쪽, DISCO ZH05·Dicing Thin Wafers

공통: 후공정마다 **"확대해서 보기"**를 둡니다. 장비 전체에서 시작해 한 부분씩 천천히 확대하며(예: 쏘잉 장비 → 블레이드 → 날 끝 → 다이아몬드 입자 하나) 원리를 움직이는 그림으로 보여줍니다. 장면마다 설명 문장이 그림의 움직임에 맞춰 하나씩 나타나고, 학생은 멈춤·이전·다음·이 장면 다시로 직접 조절합니다. 설명은 공정 데이터(processes.js)의 내용만 쓰고 검수 전으로 표시합니다.

## Q5 화면
1. **패키지 선택 화면**: 패키지 버튼 목록. 버튼을 누르면 장점, 쓰이는 곳, 대표 제품 예시, "이 패키지로 학습 시작" 버튼이 보입니다.
2. **공정 질문 화면**: 검색창, 공정 설명, 학습 자료, 출처 링크, "먼저 볼 공정" 추천
3. **공정 흐름도 화면**: 선택한 패키지의 공정이 순서대로 연결된 지도. 현재 공정 강조, 학습 완료 표시, 패키지 바꾸기 버튼
4. **시뮬레이션 화면**: 조건 슬라이더, 실행 버튼, 결과와 불량 설명
5. **Advanced Package 화면**: 첨단 패키지 카드 목록. 카드를 누르면 탭 4개(핵심 공정 / 왜 중요한가 / 쓰이는 곳 / 미래 기술)와 "먼저 볼 기본 공정" 추천, 출처 목록이 보입니다.
6. **라인 시뮬레이션 화면**: 위쪽에 공정 진행 막대(1/8, 2/8 …), 가운데에 현재 공정의 변수와 선택지 1·2·3, 아래에 "이전 공정" "다음 공정" 버튼
7. **최종 판정 화면**: 판정 결과(정상 / 신뢰성 위험 / 불량), 공정별 선택 요약, 문제가 된 선택과 이유, 출처, "이 공정 다시 학습" "처음부터 다시" 버튼

## Q6 성공 기준
- 패키지 선택 화면에서 "QFN" 버튼을 누르면 QFN의 장점과 쓰이는 곳이 보이고, "학습 시작"을 누르면 QFN 공정 흐름도가 열립니다.
- 다른 패키지로 바꾸면 흐름도의 공정 순서가 그 패키지에 맞게 바뀝니다. (예: 플립칩을 고르면 와이어 본딩 대신 범핑·플립칩 본딩이 보임)
- "쏘잉 알려줘"를 입력하면 쏘잉 설명, 선수 공정 목록, 출처가 함께 보이고, 흐름도에서 쏘잉 위치가 강조됩니다.
- 추천된 선수 공정을 누르면 그 공정 설명으로 이동하고, 학습을 마치면 흐름도에 완료로 표시됩니다.
- 시뮬레이션에서 조건 하나를 바꿔 실행하면 결과가 달라지고, 왜 달라졌는지 한 문장 설명이 보입니다.
- 라인 시뮬레이션에서 모든 공정에 권장 선택지를 고르면 최종 판정이 "정상"으로 보입니다.
- 한 공정에서 불량 선택지를 고르면 최종 판정이 "불량"으로 보이고, 원인 공정, 이유 한 문장, 출처, "이 공정 다시 학습" 버튼이 함께 보입니다.
- 앞 공정의 선택이 뒤 공정에 영향을 주는 경우(예: 웨이퍼를 너무 얇게 갈면 쏘잉에서 깨짐 위험 증가), 최종 판정 화면에 두 공정의 연결이 보입니다.
- "이전 공정"으로 돌아가 선택을 바꾸면 최종 판정이 그 선택에 맞게 다시 계산됩니다.
- 최종 판정 화면에서 모든 공정의 진단이 순서대로 보이고, 단면 그림에서 문제가 된 부위(예: 와이어)가 표시됩니다.
- 공정 설명에서 "비유로 쉽게 보기"를 누르면 비유 설명이 펼쳐지고, 다시 누르면 닫힙니다.
- Advanced Package 화면에서 "2.5D 패키지"를 누르면 핵심 공정(인터포저, TSV, 마이크로 범프 등), 중요한 이유, 쓰이는 곳, 미래 기술이 탭으로 보이고 탭마다 출처가 1개 이상 붙어 있습니다.
- Advanced Package의 핵심 공정을 누르면 그 공정을 이해하는 데 필요한 기본 공정이 추천됩니다.
- 근거 출처가 없는 질문을 하면 지어낸 답 대신 "검증된 자료에서 확인되지 않음"이 보입니다.

## 라인 시뮬레이션 데이터 초안 (QFN 기준)
[가설] 선택지와 결과는 교재·논문에서 "이론적으로 이렇게 하면 패키징이 잘 된다"고 제시한 조건을 기준으로 만듭니다. 아래는 일반적으로 알려진 경향을 정성적으로 적은 초안이며, 실제 수치 범위는 출처를 찾은 뒤 채웁니다.

### 판정 규칙
- 선택지마다 등급이 있습니다: **권장**(이론상 잘 됨) / **주의**(당장은 되지만 신뢰성 위험) / **불량**(기능 실패)
- 불량 선택지가 하나라도 있으면 최종 판정은 **불량**입니다.
- 불량은 없고 주의가 하나라도 있으면 **신뢰성 위험**입니다. 주의가 2개 이상 겹치면 불량으로 바뀌는 조합 규칙은 출처가 있을 때만 넣습니다.
- 모두 권장이면 **정상**입니다.
- 앞 공정의 선택이 뒤 공정의 등급을 바꾸는 **연결 규칙**을 둡니다. (예: 백그라인딩 "너무 얇게"를 고르면 쏘잉의 "빠른 이송 속도" 등급이 주의에서 불량으로 바뀜)
- 판정은 미리 정한 규칙표로만 계산하고 AI는 쓰지 않습니다. 같은 선택이면 항상 같은 결과가 나옵니다.

### 공정별 변수와 선택지 예시
| 공정 | 변수 | 선택지 1 | 선택지 2 | 선택지 3 | 잘못 골랐을 때 대표 불량 |
|---|---|---|---|---|---|
| 백그라인딩 | 최종 두께 | 너무 얇게 | 권장 두께 | 너무 두껍게 | 얇으면 휨·깨짐, 두꺼우면 패키지 두께 초과 |
| 웨이퍼 쏘잉 | 블레이드 이송 속도 | 느리게 | 권장 속도 | 빠르게 | 빠르면 칩핑(가장자리 깨짐)·크랙 |
| 다이 어태치 | 접착제 양 | 부족 | 권장 | 과다 | 부족하면 보이드·박리, 과다하면 접착제가 넘쳐 패드 오염 |
| 다이 어태치 | 경화 조건 | 덜 경화 | 권장 | 과경화 | 덜 경화되면 접착력 부족·박리 |
| 와이어 본딩 | 초음파 출력·하중 | 약하게 | 권장 | 강하게 | 약하면 접합 안 됨, 강하면 패드 아래 손상(크레이터링) |
| 몰딩 | 주입 속도 | 느리게 | 권장 | 빠르게 | 빠르면 와이어 쓸림(wire sweep), 느리면 미충전·보이드 |
| 마킹 | 레이저 출력 | 약하게 | 권장 | 강하게 | 약하면 식별 불가, 강하면 몰딩 손상 |
| 패키지 쏘잉 | 블레이드 상태·속도 | 마모된 블레이드 | 권장 | 너무 빠르게 | 버(burr)·칩핑, 리드 손상 |

```
연결: 없음

```

## Advanced Package 데이터 초안
[가설] 일반적으로 알려진 내용입니다. 앱에 넣기 전에 항목마다 무료 공개 출처를 붙이고 전문가 검수를 받습니다.

### 왜 중요한가 (화면의 공통 소개)
- 트랜지스터를 더 작게 만들어 성능을 올리는 방식(무어의 법칙)이 점점 어렵고 비싸지고 있습니다.
- 그래서 칩 여러 개를 하나의 패키지 안에 가깝게 붙여 성능을 올리는 방식(이종 집적, 칩렛)이 중요해졌습니다.
- AI 가속기처럼 메모리 대역폭이 많이 필요한 칩은 GPU 옆에 HBM을 붙이는 첨단 패키지가 성능을 좌우합니다.
- 패키징이 "칩을 보호하는 마지막 공정"에서 "성능을 만드는 공정"으로 바뀌고 있다는 점이 학습 포인트입니다.

### 첨단 패키지 카드
| 패키지 | 핵심 공정 | 왜 중요한가 | 쓰이는 곳 | 먼저 볼 기본 공정 |
|---|---|---|---|---|
| 2.5D (실리콘 인터포저) | 인터포저 제작, TSV, 마이크로 범프, 칩 온 웨이퍼 본딩, 언더필 | 칩 여러 개를 아주 촘촘한 배선으로 나란히 연결 | AI 가속기, GPU + HBM | 플립칩 본딩, 언더필 |
| 3D 적층 (TSV) | TSV 형성, 웨이퍼 박화, 마이크로 범프, 칩 적층 | 칩을 위로 쌓아 면적을 줄이고 연결 길이를 줄임 | HBM 메모리 | 백그라인딩, 플립칩 본딩 |
| 하이브리드 본딩 | 표면 평탄화(CMP), 구리-구리 직접 접합, 다이/웨이퍼 정렬 | 범프 없이 붙여 연결 간격을 크게 줄임 | 이미지 센서, 차세대 HBM, 3D 로직 | 웨이퍼 쏘잉, 다이 어태치 |

| 팬아웃 (고밀도) | 다이 재배치, 몰딩, 재배선층(RDL) | 기판 없이 얇고 단자를 넓게 배치 | 모바일 AP | 몰딩, WLCSP |

### 미래 기술 (탭 "앞으로 개발될 기술")

## 정보 정확성 정책
잘못된 정보를 줄이기 위해 답변을 아래 순서로 만듭니다.

1. **검수된 공정 데이터 먼저**: 패키지 설명, 공정 흐름, 선수 공정, 시뮬레이션 규칙은 미리 정리하고 전문가가 검수한 데이터에서만 가져옵니다. AI는 이 데이터를 바꾸거나 새로 만들지 않습니다.
2. **AI 보충 설명은 무료로 공개된 출처에서만**: 공정 데이터에 없는 내용은 AI가 허용 목록에 있는 무료 출처를 검색해 설명합니다. 유료 구독이 필요한 학술 DB는 쓰지 않습니다. 출처는 두 등급으로 나눕니다.
   - **1순위 (근거 출처)**: 시뮬레이션 규칙, 불량 원인, 공정 조건의 근거로 쓸 수 있습니다.
     - 논문 검색 (무료 API): OpenAlex, Semantic Scholar, Crossref
     - 무료 본문 찾기: Unpaywall, CORE, DOAJ, arXiv
     - 국내 논문: KCI(한국학술지인용색인) 공개 논문, ScienceON
     - 공개 로드맵·보고서: IEEE EPS Heterogeneous Integration Roadmap(무료 공개), 정부·공공 연구기관 보고서
     - 표준: JEDEC 무료 공개 표준(회원 가입 후 무료 내려받기 가능한 문서만)
   - **2순위 (설명 출처)**: 공정 설명, 전체 흐름, 비유처럼 학생 눈높이의 설명에만 씁니다. 시뮬레이션 규칙과 판정의 근거로는 쓰지 않습니다.
     - 대학 공개 강의: KOCW, K-MOOC, MIT OpenCourseWare
     - 업체 공식 자료: 반도체 제조사·장비사·소재사의 공식 뉴스룸과 기술 문서 (개인이 운영하는 블로그는 제외)
   - 유료 논문은 무료로 공개된 초록만 참고할 수 있고, 초록만 보고 쓴 문장에는 "초록 기준"이라고 표시합니다.
   - 2순위 출처만 있는 내용에는 "설명 출처"라고 표시해 1순위 근거와 구분합니다.
   - 개인 블로그, 커뮤니티, 출처 없는 웹 문서는 쓰지 않습니다.
3. **출처 없이는 답하지 않음**: AI 설명의 모든 문장에는 출처 링크가 붙습니다. 출처를 찾지 못하면 "검증된 자료에서 확인되지 않음"으로 표시합니다.
4. **충돌하면 공정 데이터 우선**: AI가 찾은 내용이 검수된 공정 데이터와 다르면 공정 데이터를 보여주고, 차이를 검토 목록에 기록합니다.
5. **화면에서 구분**: 검수된 데이터는 "검수됨", AI 보충 설명은 "AI 요약 · 출처 확인 권장" 표시로 구분합니다.
6. **신고**: 학생이 틀린 내용을 신고할 수 있는 버튼을 두고, 신고된 내용은 검수자가 확인합니다.

AI 답변의 오류를 완전히 없앨 수는 없으므로, 위 정책은 오류를 줄이고 오류가 생겨도 학생이 출처로 직접 확인할 수 있게 하는 데 목적이 있습니다.

## Q1 사용자 (v2)

## Q2 문제 (v2)
- 반도체 전체 공정은 범위가 넓고 자료가 흩어져 있어, 공정 하나를 따로 외우면 "앞 공정의 결과가 다음 공정의 조건을 어떻게 바꾸는지"가 연결되지 않습니다. (이 과제를 시작한 이유: 직접 만들면서 이해하려고 시작했습니다.)
- [가설] 공정 지식이 있어도 "확산부터 막고 → 측정을 의심하고 → 데이터로 원인을 가르고 → 조건을 함부로 바꾸지 않는" 현장 판단을 연습할 곳이 없습니다. 실제 현장 데이터는 공개되지 않습니다.
- 출처가 불분명한 자료에서 틀린 공정 지식을 배우기도 합니다. AI가 만든 그럴듯한 설명도 근거가 없을 수 있습니다.

## Q3 해법 (v2)
학생이 공정을 **배우고 → 조건을 바꿔 보고 → 현장 사건처럼 풀어 보게** 합니다. 결과(시뮬레이션 판정·시나리오 점수)는 AI가 아니라 미리 정한 규칙표로만 계산하고, 설명 문장마다 출처를 붙이며, 근거가 없으면 "확인되지 않음" 또는 "교육용 가설(검수 전)"이라고 밝힙니다.

## Q4 기능 3개 (v2, 동사 중심)
1. **배운다** — 공정을 고르거나 물으면 설명·애니메이션·선수 공정·흐름 속 위치를 본다.
2. **조건을 바꿔 본다** — 설비 실습, FAB 공정 시뮬레이션, PKG 라인 시뮬레이션에서 조건을 바꾸고 결과·불량·근거를 본다.
3. **현장 사건을 푼다** — 교육용 가상 사건을 초기 대응 → 데이터 수집 → 원인 분석 → 조치·검증 순서로 풀고 100점 평가와 엔지니어 보고서를 받는다.

세 기능을 돕는 기능: 시험·오답 노트, 학습 일정·노트·학습 분석, 공정 데이터 분석·불량 분석 도감, 선택 기능(구글 로그인 동기화, 내 API 키로 쓰는 AI).
벤치마킹 반영(benchmark.md): 선수 공정은 **추천하되 강제하지 않고** 바로 건너뛸 수 있게 했습니다(Khan Academy 비교에서 채택). 시뮬레이션은 조건을 바꾸면 결과가 바로 보이게 했습니다(PhET 비교).

#### 세부 기능 목록 (v1 기능 1~6에 이어 붙인 7~14)
7. **반도체 기초·전공정을 배운다**: 원자·도핑·PN 접합·트랜지스터·CMOS·FinFET·GAA와 전공정 8대 공정을 영상처럼 넘어가는 애니메이션으로 봅니다. 자막 문장마다 출처가 붙고, 배속·자막·장면 반복·이어 보기를 지원합니다(자동 재생 없음).
8. **설비를 조작한다(설비 실습, 14대)**: 전공정 6대(산화로, 노광·트랙, 건식 식각기, CVD, 이온 주입기, PVD)와 후공정 8대 장비의 상태와 조건을 정하고 가동합니다. 가동 순서대로 로그가 나오고, 문제가 있으면 그 단계에서 알람으로 멈추며, 불량·경고·정상과 원인·조치·근거를 보여줍니다. 자유 조작, 상황 실습, 라인 연결 실습(앞 장비의 결과가 뒤 장비 상태를 바꿈)을 지원합니다.

10. **현장 실무 시나리오를 푼다**: FAB 3개(CVD 막 두께 불균일, 식각 잔류물, 포토 오버레이)와 PKG 4개(와이어 본딩 접합 강도, 다이 어태치 보이드, 몰딩 박리, 파이널 테스트 수율 급락)의 교육용 가상 사건을 6단계(상황 전달 → 초기 대응 → 데이터 수집 → 원인 분석 → 조치·검증 → 평가)로 진행합니다.

## Q6 성공 기준 (v2, 행동 뒤 결과)
- 공정 검색에서 "쏘잉"을 입력하면 웨이퍼/패키지 쏘잉을 되묻고, 고르면 설명·선수 공정·출처가 보인다.

- 로그인과 API 키 없이 앱을 열어도 학습·시뮬레이션·시나리오·시험이 모두 동작한다.

### 정보 정확성 정책 (v2 개정)
잘못된 정보를 줄이기 위해 답변을 아래 순서로 만듭니다.

1. **검수된 공정 데이터 먼저**: 패키지 설명, 공정 흐름, 선수 공정, 시뮬레이션 규칙, 시나리오는 미리 정리한 데이터(`app/src/data`)에서만 가져옵니다. AI는 이 데이터를 바꾸거나 새로 만들지 않습니다.
2. **출처는 두 등급으로 나눕니다.** 유료 구독이 필요한 학술 DB는 쓰지 않습니다.
   - **1순위 (근거 출처)**: 시뮬레이션 규칙, 불량 원인, 공정 조건, 시나리오 원인 구조의 근거로 씁니다.
     - 논문: OpenAlex·Semantic Scholar·Crossref로 찾은 무료 공개 논문(Unpaywall, CORE, DOAJ, arXiv), KCI 공개 논문, ScienceON, 무료 공개 학회 논문집
     - 공개 로드맵·보고서: IEEE EPS Heterogeneous Integration Roadmap, 정부·공공 연구기관 보고서(예: NASA NEPP, NIST)
     - 표준: JEDEC 무료 공개 표준(회원 가입 후 무료 내려받기 가능한 문서만)
   - **2순위 (설명 출처)**: 공정 설명, 전체 흐름, 비유처럼 학생 눈높이의 설명에 씁니다.
     - 대학 공개 강의: KOCW, K-MOOC, MIT OpenCourseWare, 대학 클린룸 공개 자료
     - 업체 공식 자료: 반도체 제조사·장비사·소재사의 공식 뉴스룸과 기술 문서
     - 업계 전문 매체: 기자나 현업 엔지니어가 쓴 기술 기사(예: Semiconductor Engineering). 후원·광고 기사는 쓰지 않습니다.
   - 유료 논문은 무료로 공개된 초록만 참고할 수 있고, 초록만 보고 쓴 문장에는 "초록 기준"이라고 표시합니다.
   - 개인 블로그, 커뮤니티, 출처 없는 웹 문서는 쓰지 않습니다.
3. **예외 규정 — 교육용 시나리오와 설비 규칙**: 판정의 근거는 1순위 출처가 원칙입니다. 1순위 출처를 찾지 못한 설비 규칙과 현장 시나리오의 원인 구조에 한해 2순위 출처를 근거로 쓸 수 있으며, 이때 아래를 모두 지킵니다.
   - 화면에 **"설명 출처"**로 표시해 1순위 근거와 구분합니다.
   - 원문 인용문을 함께 보여 학생이 직접 확인할 수 있게 합니다.
   - **"검수 전"**으로 두고, 1순위 출처를 찾으면 바꿉니다(아래 "출처 현황"에 기록).
   - 출처가 전혀 없는 규칙은 **"교육용 가설(검수 전)"**으로 표시합니다.
4. **가상 데이터 구분**: 현장 시나리오와 데이터 분석의 사건·수치·로그는 모두 교육용 가상 데이터이며 화면에 "가상 데이터"로 표시합니다. 실제 업체·장비의 규격이 아닙니다. 사건 구조처럼 출처로 확인하지 못한 결과는 "교육용 가정"으로 밝힙니다.
5. **출처 없이는 답하지 않음**: 설명·자막·AI 설명의 모든 문장에는 출처가 붙습니다. 출처를 찾지 못하면 "검증된 자료에서 확인되지 않음"으로 표시합니다.
6. **충돌하면 공정 데이터 우선**: AI가 찾은 내용이 공정 데이터와 다르면 공정 데이터를 보여주고 차이를 검토 목록에 기록합니다.
7. **화면에서 구분**: "검수됨" / "검수 전", "근거 출처" / "설명 출처", "AI 요약 · 출처 확인 권장"을 구분해 표시합니다.
8. **신고**: 학생이 틀린 내용을 신고할 수 있는 버튼을 두고, 신고된 내용은 검수자가 확인합니다.
9. **AI는 선택 기능**: AI 문제 생성, 서술형 AI 채점, 일정 AI 조정, 학습 챗봇은 학생이 자기 API 키를 넣었을 때만 동작합니다. 시뮬레이션·시나리오 판정과 점수에는 AI를 쓰지 않습니다.

AI 답변의 오류를 완전히 없앨 수는 없으므로, 위 정책은 오류를 줄이고 오류가 생겨도 학생이 출처로 직접 확인할 수 있게 하는 데 목적이 있습니다.

### 이미지 정책 (v2 개정)
1. **앱 안의 그림은 직접 만듭니다**: 공정 개념도, 패키지·웨이퍼 단면도, 장비 입체 도식, 불량 위치 표시, 원리 도식은 모두 직접 그린 SVG입니다. 외부 그림을 따라 그리지 않고 공정 데이터의 설명을 바탕으로 그립니다. 화면에 **"교육용 도식"** 배지를 붙이고 실제 치수·모양과 다를 수 있다고 밝힙니다.
2. **실제 사진은 "예시"로만 보여줍니다**: 재사용이 허락된 사진(CC0, CC BY, CC BY-SA, 저작권자의 서면 허락)만 앱에 넣고, 사진마다 출처·저작자·라이선스를 표시합니다(현재 Wikimedia Commons 사진). 허락받지 않은 사진은 "원본에서 보기" 링크로만 엽니다. 실제 사진이 없는 장비는 사진이 있는 것처럼 꾸미지 않고 교육용 도식만 씁니다.
3. **비영리 라이선스(CC BY-NC 등)**: 앱이 무료 교육용인 동안만 직접 첨부할 수 있습니다. 유료화하면 링크로 바꿉니다.
4. **동영상**: 앱 안의 "영상"은 직접 만든 움직이는 개념도(공정 애니메이션)이며, 자막 문장마다 출처를 붙입니다. 실제 촬영 영상은 공식 채널(장비·반도체 회사, 대학·공공기관)의 유튜브 영상만 "영상으로 보기" 링크로 연결하고, 앱 안에 넣거나 내려받지 않습니다. 자동 재생하지 않습니다.
5. **정답을 미리 보여주지 않음**: 현장 시나리오에서 원인을 보여 주는 도식은 관련 데이터를 확인한 뒤에만 공개합니다. 보고된 증상만 그린 도식은 처음부터 보여줍니다.
6. **그림도 검수 대상**: 직접 그린 그림도 공정 설명과 함께 검수받고, 검수 전에는 "검수 전"으로 표시합니다.

### 범위 밖 (v2 개정)
- 실제 장비 수치와 똑같은 정밀 물리 시뮬레이션 (시뮬레이션은 정성적 단계와 교육용 상대 지표 0~100만 씁니다)
- 실제 회사의 생산 데이터, 실제 장비 사진·촬영 영상의 자체 제작
