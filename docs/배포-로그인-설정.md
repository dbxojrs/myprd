# 배포 + 구글 로그인 설정 (Netlify · Supabase)

8주차 실배포 순서(GitHub → Netlify, DB는 Supabase)를 공정 튜터에 맞춘 안내입니다.
공정 튜터는 서버가 없는 앱이라 **DB 옮기기·서버 함수는 필요 없고**, Supabase는 구글 로그인과 공부 기록 저장에만 씁니다.
로그인을 설정하지 않아도 앱은 그대로 동작합니다(기록은 그 브라우저에만 저장).

순서: ① Supabase 프로젝트 → ② 구글 로그인 키 → ③ Netlify 배포 → ④ 주소 연결 → ⑤ 확인

---

## ① Supabase 프로젝트 만들기

1. https://supabase.com → GitHub로 로그인 → **New project**
   - 이름 `myprd` · DB 비밀번호는 따로 보관 · 지역은 가까운 곳(Seoul/Tokyo)
2. 왼쪽 **SQL Editor** → `app/supabase/schema.sql` 내용을 붙여 넣고 **Run**
   - `study_data` 표가 생기고 RLS(본인 줄만 읽고 쓰기)가 켜집니다.
3. **Project Settings → API**(또는 위쪽 **Connect**)에서 두 값을 메모
   - `Project URL` → `VITE_SUPABASE_URL`
   - `anon` `public` 키 → `VITE_SUPABASE_ANON_KEY` (공개 키라 화면 코드에 들어가도 됩니다. `service_role` 키는 절대 쓰지 않습니다)

## ② 구글 로그인 키 만들기

1. https://console.cloud.google.com → 프로젝트 만들기
2. **API 및 서비스 → OAuth 동의 화면**: 외부(External), 앱 이름 `반도체 공정 튜터`, 지원 이메일 입력 → 저장
3. **사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID**
   - 유형: **웹 애플리케이션**
   - 승인된 리디렉션 URI: `https://<내 프로젝트>.supabase.co/auth/v1/callback`
     (Supabase **Authentication → Sign In / Providers → Google** 화면에 정확한 주소가 나옵니다)
4. 만들어진 **클라이언트 ID**와 **클라이언트 보안 비밀**을 복사
5. Supabase **Authentication → Sign In / Providers → Google** 켜기 → 두 값 붙여 넣기 → Save

## ③ Netlify 배포

1. https://app.netlify.com → GitHub로 로그인 → **Add new project → Import an existing project → GitHub**
2. 저장소 목록에서 **myprd** 선택 (안 보이면 아래 "GitHub 권한 설정"에서 myprd 허용 → Save → 다시 고르기)
3. 빌드 설정은 저장소의 `netlify.toml`이 자동으로 채웁니다
   - Base directory `app` · Build command `npm ci && npm run build` · Publish directory `dist`
4. **Add environment variables**에 두 개 입력 (채팅창이 아니라 Netlify 칸에)
   ```
   VITE_SUPABASE_URL      = ①에서 복사한 Project URL
   VITE_SUPABASE_ANON_KEY = ①에서 복사한 anon public 키
   ```
5. **Deploy** → `https://<이름>.netlify.app` 주소가 생깁니다
   - 이름은 Project configuration → Change project name에서 바꿀 수 있습니다(예: `myprd-tutor`)
   - Netlify에서 **Make public**을 눌러야 다른 사람도 볼 수 있습니다

> 환경 변수를 나중에 바꾸면 **Deploys → Trigger deploy**로 다시 배포해야 반영됩니다(VITE_ 값은 빌드할 때 들어갑니다).

## ④ 로그인 주소 연결 (Supabase)

**Authentication → URL Configuration**
- Site URL: `https://<이름>.netlify.app`
- Redirect URLs에 추가:
  - `https://<이름>.netlify.app/**`
  - `http://localhost:3068/**` (내 컴퓨터 개발 서버에서도 로그인하려면)

## ⑤ 확인

- [ ] `https://…netlify.app`에 자물쇠(https)가 있고 스마트폰에서 열림
- [ ] 왼쪽 메뉴 아래 **구글로 로그인** → 구글 계정 선택 → 이름·사진이 보임
- [ ] 노트를 하나 쓰고 몇 초 뒤 "계정에 저장됨 ✓" 표시
- [ ] 다른 기기(스마트폰)에서 같은 구글 계정으로 로그인 → 같은 노트·진도가 보임
- [ ] Supabase **Table Editor → study_data**에 내 줄이 한 줄 있고, 오른쪽 위가 **RLS enabled**
- [ ] GitHub 저장소에 `.env` 파일이 없음(`.env.example`만 있음)

## 내 컴퓨터(3068)에서 로그인 시험하기

`app/.env` 파일을 만들고(커밋하지 않음) 두 값을 넣은 뒤 개발 서버를 다시 켭니다.
```
VITE_SUPABASE_URL=https://<내 프로젝트>.supabase.co
VITE_SUPABASE_ANON_KEY=<anon public 키>
```

## 막혔을 때

| 증상 | 해결 |
|---|---|
| Build failed | Netlify Deploys의 빌드 로그 전체를 확인 · Node 버전은 netlify.toml에서 22 |
| 로그인 버튼이 안 보임 | Netlify 환경 변수 이름이 `VITE_`로 시작하는지 확인 → 다시 배포 |
| 구글 화면에서 `redirect_uri_mismatch` | ②-3의 리디렉션 URI가 Supabase Google 화면의 Callback URL과 똑같은지 |
| 로그인 뒤 localhost로 돌아감 | ④ Site URL·Redirect URLs에 Netlify 주소가 있는지 |
| "계정에 저장하지 못했습니다" | ①-2 SQL을 실행했는지(`study_data` 표·RLS 정책) |
| 구글 화면에 "확인되지 않은 앱" | OAuth 동의 화면이 테스트 상태 → 테스트 사용자에 내 계정을 추가하거나 게시(Publish) |

## 무엇이 계정에 저장되나

노트·템플릿, 공정 진도, 공부 일정과 체크, 공부한 날, 시험 기록·오답, 심화 주관식 기록, 실무 연습 답안, 현장 실무 시나리오 진행·점수 기록, 엔지니어 보고서(8D·5 Why·피시본), 챗봇 대화.
두 기기에서 따로 쓴 노트·보고서는 로그인할 때 항목별로 더 최근에 고친 쪽으로 합쳐집니다.
**저장하지 않는 것**: Claude API 키(그 브라우저에만), 창 위치·메뉴 접기·다크 모드 같은 기기별 화면 설정.
