# 새 기능 3개: Claude Code 작업 프롬프트

> 이 파일은 고쳐 가며 쓰는 초안입니다.
> 추천 순서: **② UI(떠 있는 동그라미·창) → ③ 개인 노트 → ① 챗봇**
> (②에서 만드는 "떠 있는 동그라미 + 창"을 ③ 노트와 ① 챗봇이 같이 쓰기 때문)
> 프롬프트 하나 = 브랜치 하나 = 커밋 하나. 한 번에 하나씩 붙여 넣기.

## 정한 것
- 노트·챗봇은 화면 아래 **떠 있는 동그라미**에서 연다. 동그라미와 창은 끌어서 옮기고, 키우고 줄일 수 있다.
  **어느 페이지에서든** 창이 열린 채로 화면을 옮겨 다니며 쓸 수 있고, **노트와 챗봇 창을 동시에** 열어 둘 수 있다.
- 챗봇 말투: **합니다체**
- 모델: **사용자가 직접 고른다.** 본인 API 키를 넣으면 그 키로 쓸 수 있는 모델 목록을 불러와 고르게 한다.
- **모바일 화면(폭 375px~)도 지원한다.**

## ② UI: 떠 있는 동그라미 + 옮기고 키우고 줄이는 창, 접기/펼치기

**브랜치:** `feature/floating-ui`

```
목표: 어느 화면에서든 노트·챗봇을 띄워 놓고 공부하면서 동시에 쓸 수 있게 한다.
또 화면이 복잡해 보이지 않게, 필요한 것만 펼쳐 보는 방식으로 바꾼다.
원칙: "기본은 핵심만 보이고, 클릭하면 나온다. 한 번 정한 위치·크기·접힘 상태는 기억한다."

1. 떠 있는 동그라미 (components/float/FloatBubble.jsx)
   - 화면 오른쪽 아래에 동그라미 2개: 📝 노트, 💬 질문하기. 지름 56px, 그림자, 서로 12px 간격.
   - 끌어서 옮기기: Pointer Events(pointerdown/move/up, setPointerCapture)로 마우스·터치 모두 지원.
     · 6px 넘게 움직이면 "끌기", 그보다 적으면 "클릭"으로 본다(끌다가 창이 열리지 않게).
     · 손을 떼면 가까운 왼쪽/오른쪽 가장자리에 붙는다(150ms 애니메이션). 화면 밖으로 못 나간다.
     · 위치는 화면 비율(%)로 저장 → 'tutor.float.bubble.<notes|chat>'. 창 크기가 바뀌거나
       화면을 돌려도(가로/세로) 화면 안으로 다시 맞춘다.
   - 클릭하면 해당 창(FloatWindow)이 열리고 동그라미는 숨는다. 창을 "줄이기" 하면 다시 동그라미가 된다.
   - 동그라미에 작은 점 표시: 노트는 "작성 중인 글 있음", 챗봇은 "답변 도착(창이 줄어 있을 때)".
   - 키보드: Alt+N 노트, Alt+K 질문하기로 열고 닫기. 동그라미 title에 단축키 표시.

2. 떠 있는 창 (components/float/FloatWindow.jsx)
   - 상태 3가지: 동그라미(줄임) / 보통 창 / 크게(데스크톱: 화면의 오른쪽 절반, 모바일: 전체 화면).
   - 머리줄: 제목, [— 줄이기] [□ 크게/원래대로] [✕ 닫기]. 머리줄을 더블클릭해도 크게/원래대로.
   - 데스크톱(>= 960px):
     · 머리줄을 끌어 어디로든 옮긴다(화면 밖으로 반 이상 나가지 않게).
     · 오른쪽 아래 모서리를 끌어 크기 조절. 최소 300×240, 최대 화면의 90%.
     · 기본 크기 380×520. 처음 열 때 동그라미 근처에 뜬다.
     · 노트 창과 챗봇 창을 동시에 열 수 있고, 클릭한 창이 앞으로 온다(z-index 순서 관리).
     · 창 뒤의 본문은 그대로 클릭·스크롤·입력할 수 있다(배경을 막는 덮개 없음).
   - 모바일(< 960px):
     · 창은 화면 아래에서 올라오는 시트. 높이 3단: 낮게(35%) / 중간(65%) / 전체(100%).
       위쪽 손잡이(가로 막대)를 위아래로 끌면 가까운 단으로 붙는다. 아래로 끝까지 끌면 줄이기(동그라미로).
     · 낮게·중간일 때는 시트 위쪽 본문을 계속 보고 스크롤할 수 있다(덮개 없음) → 공정 설명을 보며 노트 쓰기.
     · 한 번에 시트 하나만 보인다. 다른 하나는 동그라미로 남고, 누르면 서로 바뀐다(위에 탭 2개로도 전환).
     · 키보드가 올라오면 visualViewport로 높이를 다시 계산해 입력칸이 가려지지 않게 한다.
     · 아이폰 하단 홈 막대를 피하도록 env(safe-area-inset-bottom) 여백을 준다.
   - 창 위치·크기·상태는 'tutor.float.win.<notes|chat>'에 저장. 새로고침해도 그대로.
   - prefers-reduced-motion이면 움직임 애니메이션을 끈다.
   - Esc는 맨 앞 창을 줄인다. 닫으면 포커스는 그 창의 동그라미로 돌아간다.

3. 어느 페이지든 유지
   - 동그라미와 창은 App.jsx의 <main> 바깥(최상위)에 한 번만 그린다.
     screen이 바뀌어도 다시 만들어지지 않게 해서, 쓰던 글·스크롤 위치·대화가 그대로 남는다.
   - App이 "지금 보고 있는 대상"을 계산해 창에 넘긴다:
     { kind:'process', id, label } (공정 상세) / { kind:'machine', id, label } (설비 실습) /
     { kind:'quiz' } / null (홈 등). 창은 이걸 보고 "📍 지금: 다이싱"을 표시한다.
   - 이 단계에서는 창 안에 "준비 중" 글만 넣는다(③, ①에서 채움).

4. 이미 있는 화면에 접기 적용 (components/ui/Collapsible.jsx)
   - Collapsible: 제목 줄을 누르면 접히고 펼쳐지는 상자.
     props: id, title, defaultOpen, badge, children.
     제목 줄은 <button aria-expanded aria-controls>, Enter/Space로도 동작. ▸/▾, 200ms 높이 애니메이션.
     열림 상태는 'tutor.ui.open.<id>'에 기억.
   - 상단 app-subbar: [▴ 메뉴 접기] 버튼. 접으면 얇은 줄만 남고 누르면 다시 펼침.
     모바일에서는 top-tabs와 subtabs를 가로 스크롤 한 줄로 만들고(줄바꿈 없음), 기본으로 subbar를 접어 둔다.
   - FlowBar: 접으면 "현재 공정: 다이싱 (5/12)" 한 줄만.
   - ProcessQuery 공정 상세: 섹션별 Collapsible.
     기본 펼침: 요약, 입력·결과, 세부 단계 / 기본 접힘: 핵심 용어, 선행 공정, 비유, 영상, 출처.
     위에 [모두 펼치기] [모두 접기].
   - MachineSim: 가동 로그를 Collapsible로(알람이 생기면 자동으로 펼침).
   - 집중 모드 토글(header 오른쪽): 켜면 subbar·FlowBar·footer를 숨기고 본문만. 'tutor.ui.focus'.

5. 하지 말 것
   - 기존 화면의 내용·데이터·판정 로직은 바꾸지 않는다(보이고 숨는 방식만 바꾼다).
   - App.jsx의 screen 전환 구조는 바꾸지 않는다.

확인 방법도 알려줘:
- 데스크톱: 동그라미 끌기 → 가장자리에 붙는지, 노트·챗봇 창 동시에 열고 옮기고 크기 바꾸기,
  창을 연 채 다른 메뉴로 이동 → 창과 쓰던 글이 그대로인지, 새로고침 → 위치·크기 유지.
- 모바일(개발자 도구 375×667, 터치 모드): 동그라미 손가락으로 끌기, 시트 손잡이로 3단 조절,
  시트를 낮게 둔 채 본문 스크롤, 입력칸 눌러 키보드가 올라와도 입력칸이 보이는지, 가로 스크롤 없는지.
- Tab 키만으로 동그라미·창 버튼·접기 버튼을 모두 쓸 수 있는지.
```

## ③ 개인 노트 정리 칸

**브랜치:** `feature/notes`  (② 머지 후)

```
목표: 공부하면서 떠오른 것을 어느 화면에서든 바로 적고, 나중에 공정별로 모아 복습한다.
위치: ②의 📝 떠 있는 창 안 + 메뉴에 "내 노트" 전체 화면 1개.

1. 데이터 (lib/notes.js)
   - 저장 키: 'tutor.notes' (배열)
   - 노트 모양:
     { id, title, body, ref: { kind: 'process'|'machine'|'quiz'|'free', id, label } | null,
       tags: string[], pinned: boolean, createdAt, updatedAt }
   - 함수: addNote, updateNote, deleteNote, notesFor(ref), searchNotes(text, tag)
   - 여러 컴포넌트(창, 내 노트 화면)가 같은 데이터를 보므로 apiKey.js처럼 useSyncExternalStore로 공유.
   - 다른 탭에서 고친 내용은 window 'storage' 이벤트로 받아 반영.
   - 저장 실패(용량 초과 등) 시 "브라우저 저장 공간이 부족합니다" 알림, 쓰던 글은 지우지 않는다.

2. 떠 있는 노트 창
   - 위쪽: "📍 지금: 다이싱" + [이 공정 노트 | 전체 노트] 전환.
     화면을 옮기면 목록은 새 공정으로 바뀌지만, 지금 쓰고 있는 노트는 닫히지 않고 그대로 남는다.
   - [+ 새 노트]: 대상(ref)을 지금 보는 공정으로 자동 지정. 대상 칩을 눌러 바꾸거나 "대상 없음"으로.
   - 자동 저장: 입력을 멈추고 0.8초 뒤 저장, 머리에 "저장됨 ✓". 창을 줄이거나 닫을 때도 즉시 저장.
   - 본문 서식은 간단하게: 줄 앞 "- " 목록, "**굵게**", "==형광펜==".
     (dangerouslySetInnerHTML 금지, 직접 파싱해 React 요소로 그린다.)
     작성 칸 위에 [• 목록] [B] [형광펜] 버튼 — 모바일에서 기호 입력이 번거로우므로.
   - 노트마다 📌 고정, 태그 추가(#입력 후 Enter), 삭제(확인 + 5초 안에 [되돌리기]).
   - 모바일: 목록 화면 ↔ 작성 화면을 한 시트 안에서 전환(← 뒤로 버튼). 작성 칸은 font-size 16px 이상
     (iOS가 자동으로 확대하지 않게).

3. 다른 화면에서 노트로 보내기
   - 공정 상세에서 글자를 선택하면 작은 [📝 노트에 추가] 버튼이 선택 영역 근처에 뜬다
     (모바일은 길게 눌러 선택했을 때 화면 아래 고정 버튼으로). 누르면 노트 창이 열리고
     지금 쓰는 노트 끝에 인용("> ...")으로 붙는다. 쓰는 노트가 없으면 새 노트로.
   - 시험 해설·오답 노트의 각 문제에 [📝 노트로]: 문제·정답·해설을 복사(ref.kind='quiz').
   - ① 챗봇 답변에도 같은 버튼을 붙일 수 있게 addNote·appendToCurrentNote를 공용으로 둔다.

4. "내 노트" 전체 화면 (menu.js에 [시험 그룹 안 / 새 그룹 "내 공부" — 하나 고르기])
   - 데스크톱: 왼쪽 검색창·태그 목록·묶어 보기(공정 단계별 / 태그별 / 날짜순), 오른쪽 노트 카드.
     모바일: 검색·거르기는 위쪽 접는 영역으로, 카드는 한 줄에 하나.
   - 공정 단계별은 STAGE_ORDER 순서로 "전공정 > 포토"처럼 묶는다.
     카드의 "다이싱"을 누르면 그 공정 상세로 이동(onOpenProcess).
   - [복습 모드]: 노트를 하나씩 크게, 본문은 가려 두고 눌러서 드러내기. 모바일은 좌우로 밀어 다음/이전.
   - 내보내기: 전체를 .md 파일로(공정별 제목 아래 노트). 백업용 .json 내보내기/가져오기
     (형식 검사 후 id가 겹치면 건너뛰기).

5. 하지 말 것
   - 노트를 서버나 AI로 보내지 않는다(① 챗봇에서 사용자가 "노트 같이 보내기"를 켠 경우만 예외).
   - 공정 데이터 파일은 고치지 않는다.

확인 방법: 다이싱 화면에서 노트 쓰다가 포토 화면으로 이동 → 쓰던 노트가 그대로인지,
새로고침 → 공정별로 맞는 노트만 보이는지, 글 선택 → 노트에 추가, 검색·태그 거르기,
.md 내보내기 내용, 사생활 보호 창(저장 불가)에서도 화면이 깨지지 않는지, 모바일에서 서식 버튼·복습 밀기.
```

## ① 공부를 도와주는 챗봇

**브랜치:** `feature/study-chat`  (②, ③ 머지 후)

### 1-A. 개발용 프롬프트 (Claude Code에 붙여 넣기)

```
목표: 어느 화면에서든 💬 동그라미로 "지금 보고 있는 공정·설비"에 대해 묻고 답을 듣는 공부용 챗봇.
기존 lib/aiTutor.js의 키 관리(useApiKey), 오류 문구(aiErrorText), contextFor()를 재사용한다.

1. 모델을 사용자가 고르게 (lib/apiKey.js 확장 + AiKeyBox 수정)
   - 키를 연결하면 client.models.list()로 그 키로 쓸 수 있는 모델 목록을 불러와 드롭다운으로 보여준다.
     목록은 display_name으로 표시하고, 실패하면 "모델 ID 직접 입력" 칸만 보여준다.
   - 고른 모델은 'tutor.aiModel'에 저장(키와 달리 모델 이름은 늘 저장해도 됨). 기본값은 목록의 첫 번째.

모바일에서 시트 낮게 두고 본문 보면서 질문하기.
```

### 1-B. 챗봇 시스템 프롬프트 (lib/studyChat.js에 들어갈 내용)

```
당신은 "반도체 공정 튜터" 앱 안에 있는 공부 도우미입니다.
사용자는 반도체 전공 학생이거나 FAB·OSAT 신입 엔지니어이며, 지금 앱에서 특정 공정이나 설비를 공부하고 있습니다.

[근거]
- 사실에 관한 말은 모두 이 메시지에 들어 있는 APP DATA(그리고 사용자가 보낸 NOTES)만 근거로 합니다.
- APP DATA로 뒷받침되지 않는 내용은 추측하지 말고 "앱 자료에서 확인되지 않음"이라고 말합니다.
  일반적인 배경 지식을 덧붙일 때는 반드시 "(일반 지식 · 앱 자료 밖)"이라고 표시합니다.
- 숫자, 장비 회사 이름, 논문·출처를 APP DATA에 없는 것으로 지어내지 않습니다.
- 설비나 라인의 정상/불량 판정은 하지 않습니다. 판정은 앱의 설비 실습 화면에서 규칙표로 확인하도록 안내합니다.
- NOTES는 학생이 쓴 메모라 틀릴 수 있습니다. APP DATA와 다르면 정중하게 바로잡습니다.

[말투와 형식]
- 한국어 합니다체로 씁니다. (예: "이 공정은 웨이퍼를 개별 다이로 자르는 단계입니다.")
- 현장 용어를 쓰고, 처음 나올 때만 영어를 괄호로 붙입니다. 예: 식각(Etch), 다이 어태치(Die Attach).
- 답은 짧게 씁니다: 기본 3~6문장 또는 항목 5개 이하. 화면이 작은 창이므로 긴 표는 쓰지 않습니다.
  더 알고 싶으면 이어서 질문하도록 안내합니다.
- 공정을 설명할 때는 가능하면 "앞 공정의 결과 → 이 공정의 조건 → 다음 공정에 주는 영향" 흐름으로 잇습니다.
- 필요하면 답 끝에 한 줄로 "다음에 볼 것: ○○"을 제안합니다(APP DATA에 있는 공정·용어만).

[모드]
- 설명: 질문에 바로 답합니다. 어려운 용어가 나오면 한 줄 풀이를 붙입니다.
- 비유: 먼저 일상 비유 하나로 감을 잡게 하고, 이어서 "실제로는"으로 정확한 설명을 합니다.
  비유 때문에 잘못 이해할 수 있는 부분이 있으면 한 줄로 짚습니다.
- 코칭: 답을 바로 주지 않습니다. 학생이 스스로 떠올리도록 질문을 한 번에 하나만 합니다.
  두 번 연속 막히면 힌트를 주고, 세 번째에는 답과 이유를 알려 줍니다.
- 퀴즈: APP DATA로 한 번에 한 문제만 냅니다(4지선다 또는 단답). 용어 암기보다
  "이 조건이면 무슨 일이 생기는가", "이 증상의 원인과 조치는 무엇인가" 같은 상황 판단 문제를 우선합니다.
  학생이 답하면 정답 여부, 이유, 근거가 된 APP DATA 문장을 짧게 알려 주고 다음 문제를 낼지 묻습니다.

[하지 않을 것]
- 앱의 공부 범위(반도체 공정·설비·패키징)와 관계없는 요청은 짧게 거절하고 공부 주제로 돌립니다.
- 시험 정답만 달라는 요청에도 이유를 함께 설명합니다.
```
